# etl-banks-ar

Personal finance management application for parsing and categorizing bank transactions from Argentine banks.

## Environment

Backend runtime configuration lives in `server/.env`.

```bash
cp server/.env.example server/.env
```

Optional deployment defaults for the public deploy script live in `.env` at the repo root.

```bash
cp .env.example .env
```

## Quick Deployment

The public deployment script is generic. Configure it with env vars from `.env` or pass flags directly.

```bash
# Full deployment
./deploy.sh --host user@example-host

# Full deployment with explicit target paths
./deploy.sh \
  --host user@example-host \
  --backend-path /srv/etl-banks-ar/api \
  --frontend-path /srv/etl-banks-ar/ui \
  --service etl-banks-ar-api

# Deploy only
./deploy.sh --host user@example-host --skip-build
```

Run `./deploy.sh --help` for all options.

## Mobile app (offline-first PWA)

The web UI in `app/` is also the phone app: an installable PWA that keeps a copy of the
workspace on the device and works without a connection.

- **Reads** (overview, records, planned spending, areas, insights, exchange rates) come from
  the local copy, stored in IndexedDB.
- **Writes** to transactions, planned spending (including "mark paid"), areas and categories
  are saved locally and queued. They are sent when the server is reachable again.
- **Sync** runs when the app opens, when it returns to the foreground, when the connection
  comes back, every minute while visible, and after each change. It does not run while the
  app is closed. The cloud icon shows the state and the number of unsent changes; tap it to
  sync now.
- **Conflicts**: if the same record changed on the phone and on the server, the most recent
  change wins.
- **Server only**: AI chat, PDF import, workspace management and editing exchange rates.

How it works: `app/src/local` (local database and the calculations the server does in SQL),
`app/src/sync/engine.ts` (push/pull cycle), `server/internal/services/sync.go`
(`GET /workspaces/:id/sync`, `POST /workspaces/:id/sync/push`).

### Using it from a phone

Open the server's address in Chrome on the phone, sign in, and let the first sync finish.
If the server's address changes later, set the new one in the app: **Server** on the login
screen, or the server icon in the menu.

How well "offline" works depends on how the app is reached, because browsers only allow
service workers (what lets the app start with no network, and be installed) on secure
origins:

| Opened as | Works online | Keeps data and queues changes offline | Starts with no network, installable |
|---|---|---|---|
| `http://<lan-ip>:<port>` | yes | yes, while the tab stays open | no |
| `https://<name>` with a certificate the phone trusts | yes | yes | yes |

Ways to get the second row on a home network:

- **A local HTTPS name.** Put the UI behind a reverse proxy that serves HTTPS with its own
  CA (for example Caddy with `tls internal`), give it a name in the local DNS, and install
  that CA's root certificate on the phone (Android: Settings → Security → Install a
  certificate → CA certificate). Then open `https://<name>` and choose **Install app**.
- **Tailscale.** Enable MagicDNS and HTTPS certificates in the admin console, run
  `sudo tailscale serve --bg <ui-port>` on the server, and open the
  `https://<host>.<tailnet>.ts.net` address it prints. Also works away from home.
- **A Chrome flag, for one phone.** In `chrome://flags`, add `http://<lan-ip>:<port>` to
  *Insecure origins treated as secure* and relaunch Chrome.

Set `BASE_URL` for the API to whichever address people use, so invite links point there.

### Trying it locally

```bash
cd server && go run ./cmd/api            # API on :8080
cd app && npm install && npm run build && npx vite preview   # UI on http://localhost:4173
```

Use the production build (`vite preview`), not `npm run dev`: the service worker that makes
the app load offline is only generated by the build. `localhost` counts as a secure origin,
so no HTTPS is needed for this. To simulate being offline, open Chrome DevTools → Network →
**Offline** (or stop the API), make some changes, then go back online and watch them sync.

Tests: `cd server && go test ./...` and `cd app && npm test`.
